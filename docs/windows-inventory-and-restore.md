# Обследование Windows и подготовка инструкции восстановления

Этот документ задаёт порядок будущей **инвентаризации игрового ПК** и подготовки приватной инструкции по восстановлению. Он не является снимком текущей системы и не содержит готовых команд для применения твиков.

## Результат обследования

После read-only обследования подготовить приватный файл `restore-current-pc.md` вне публичного fork. Для каждого пункта указать: текущее значение, где оно прочитано, пользователя или область действия, способ безопасного экспорта, место резервной копии, точные шаги восстановления, зависимость от версии Windows/программы и способ проверки после восстановления. Неизвестное помечать как «не проверено».

Составить отдельный список желаемых изменений. Текущее состояние и желаемую конфигурацию не смешивать. Если отдельная задача уже разрешает экспорт и резервное копирование, выполнить их в её границах без повторного согласования. Импорт, установка, удаление и изменение параметров требуют отдельного разрешения либо явного включения в задачу.

## 1. Система и программы

- Уточнить точную редакцию, build, архитектуру и лицензионные ограничения Windows IoT Enterprise LTSC; учётные записи, права, локали, диски и расположение пользовательских данных.
- Составить перечень установленного софта из WinGet, Windows Apps, списка установленных программ и portable-каталогов. Зафиксировать версии, источники, идентификаторы пакетов, фактическое расположение и область установки (`user`/`machine`/неизвестно). Отдельно отметить программы, которые нужны лишь на сервере сборки.
- Проверить драйверы чипсета, GPU, аудио, сети и периферии, игровые платформы, античит, Store/Xbox/Game Pass при использовании, Windows Features, WSL/виртуализацию и зависимости, важные для игр.
- Зафиксировать текущие Windows Update, Defender, брандмауэр, питание, автозагрузку, службы и применённые твики WinUtil. Для каждого предполагаемого твика записать исходное значение и способ отката; не делать массовый debloat.
- Составить точный список программ для fork: что уже есть в WinUtil, чего не хватает, какие пакеты доступны через WinGet, где требуется другой способ установки и какие лицензии/учётные записи понадобятся.

## 2. Пользовательская среда и интерфейс

- Сохранить список профилей, настроек и расширений Vivaldi; уточнить, включена ли синхронизация. Перед копированием профиля закрыть браузер. Пароли, cookies, токены и ключи синхронизации хранить только в защищённой резервной копии, не в документации или репозитории.
- Зафиксировать настройки Проводника, панели задач, меню «Пуск», мониторов, масштабирования, звука, устройств ввода и сетевых интерфейсов. Уточнить, какие из них относятся к конкретному пользователю.
- Проверить отключение акселерации мыши по фактическим параметрам Windows и сопутствующего ПО. Записать DPI, polling rate и игровые настройки мыши, если они влияют на результат.
- Проверить пункты контекстного меню Проводника **Open Windows Terminal** и **Open Windows Terminal (Admin)**, как на предоставленном снимке: где они доступны, какие команды и права используют, какие записи/механизм создают их, как экспортировать и восстановить без дубликатов.
- Уточнить точные названия и версии «fun control» и «msi light»; не предполагать, что это определённые продукты. Затем сохранить их профили и настройки с проверкой импорта.
- Для MSI Afterburner сохранить профиль, кривую/значения андервольта GPU, автозапуск и связанные настройки RTSS. После восстановления проверять на той же модели GPU и версии драйвера; не применять старый профиль к другой карте вслепую.

## 3. Доступ и резервные копии

- Описать `~/.ssh/config`, используемые алиасы `docker` и `openwrt`, known_hosts, публичные ключи и права файлов. Для приватных ключей, passphrase, recovery/backup keys и иных секретов указать только тип, назначение и **место защищённой копии**; содержимое не печатать в логи и не включать в fork.
- Уточнить, что пользователь называет «backup ключом»: запасной SSH-ключ, ключ восстановления шифрования, ключ аккаунта или другое. Зафиксировать процедуру проверки входа по резервному способу без раскрытия секрета.
- Сохранить личный глобальный `AGENTS.md` Codex и связанные пользовательские настройки отдельно от публичного проекта; записать их реальные пути и способ восстановления. Учитывать, что проектный `AGENTS.md` действует только в проекте.
- Составить карту резервного копирования: источник → защищённое место хранения → способ экспорта → проверка читаемости/целостности → порядок восстановления. Шифрование и доступ к копии должны сохраняться после переустановки Windows.

## 4. Разделение ролей и проверка восстановления

- Описать, какие операции остаются на игровом ПК, какие сборки выполняются через `ssh docker` и Samba, а какие сетевые изменения относятся к `ssh openwrt`. Проверить доступность каждого узла и зафиксировать реальные каталоги/протоколы до написания команд.
- Упорядочить восстановление: Windows и драйверы → сеть и безопасный доступ → WinGet/нужные компоненты → fork WinUtil и выбранные твики → программы → профили и интерфейс → проверка игр и периферии. Для действий, зависящих от Store или аккаунтов, указать предварительные условия.
- Для каждого шага описать проверку результата и откат. Подтверждённый экспорт ещё не доказывает успешный импорт; полную проверку выполнять на тестовой системе либо при реальном восстановлении и честно отмечать границы проверки.
